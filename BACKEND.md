# Theme Gallery backend

## Operations and providers

Reads `/usr/share/omarchy/themes/<slug>` and `$HOME/.config/omarchy/themes/<slug>`; merges stock then user overlay by canonical slug, never by normalized display labels. Slugs are restricted to `[a-z0-9][a-z0-9-]{0,63}` because the stock setter normalizes names. A symlinked/non-directory user shadow blocks that stock slug too. Current state comes from `$HOME/.local/state/omarchy/current/{theme.name,theme.generation}`. Previews prefer user preview.png/jpg/jpeg/webp/bmp, then that layer's first safe background, with stock fallback; colors.toml accent is bounded TOML and a validated hex color. Invalid metadata does not crash browsing.

Primary `apply` calls existing `omarchy-theme-set <canonical-slug>` with OMARCHY_PATH fixed to the installed tree, OMARCHY_THEME_WAIT=1, offline/headless flags disabled and skip-background unset. This is the underlying existing `omarchy theme set` provider, not a new theming engine. The selected trees are checked for symlinks/special files and bounded to 2048 visible entries, depth 5 and 32 MiB/file. Their source signature is rechecked after application. Success requires zero exit, no stderr warnings, matching theme.name and a newly written theme.generation. A no-op exit0 is not confirmation.

The native setter's `snapshot_background_path` uses `ln` (with a copy fallback), then removes transition snapshots. Hard-link creation/removal changes source ctime without changing image content. Only direct `backgrounds/*.{png,jpg,jpeg,gif,webp,bmp}` files (case-insensitive suffixes, matching native still selection) therefore use SHA-256 content plus device, inode, size, mtime, mode, uid and gid instead of cross-operation ctime. Hashing is capped at **128 MiB total per signature across the selected stock and user layers**, not per layer; over-budget themes fail before the provider. Each read is bounded to the admitted file size plus one overflow byte, at most 32 MiB plus one. The opened FD must match the scanned file's complete fingerprint including ctime before reading and still match after reading, with the exact admitted length. Same-size in-place edits with restored mtime are rejected by content comparison; changes during the read are rejected even if they only change ctime. All directories, other files, nested backgrounds and videos retain their original full metadata fingerprints, including ctime. No trust roots or setter flags change, and catalog browsing does not hash images.

**Provider deadline is 22 seconds, leaving headroom inside the parent's 30-second action watchdog.** Slow retints/hooks can therefore time out and report partial state rather than fake completion. A timeout/nonzero/warning reports possible partial state, not success. Stderr warnings remain visible as an actionable partial-retint warning without leaking arbitrary hook output.

## Restore and limits

One-level `restore` reapplies the previous still-installed canonical theme through the same provider. The durable receipt stores the original selected ID, old name, applied name and generation. Restore refuses external theme/generation changes and revalidates the old theme tree. After confirmed restore the receipt is removed. If no known previous theme exists, Restore is not advertised.

This is a **compensating theme selection, not generic rollback**: user theme-set hooks, generated configs, application retints, keyboard/browser policies and Omarchy's machine mirroring can have broad effects. Some installed hooks suppress their failures. Silent downstream failures and pixel presentation are not provable from name/generation alone. Source-tree races are detected before/after, not eliminated inside the existing setter; use only trusted installed themes and do not edit their trees while applying. No hooks/config files are executed directly by this backend and nothing is applied on hover/selection/catalog.

## Contract and safety

System Python 3.11+ / standard library only; tested with installed Python 3.14.8. No cross-plugin imports, new packages, framework, daemon, network, installer, or autostart. Runtime paths do not depend on cwd. The UI calls:

```
/usr/bin/python3 runtime/0.2.1/backend.py catalog
/usr/bin/python3 runtime/0.2.1/backend.py action --id ID --verb VERB --apply
```

Catalog returns one JSON object with bounded unique rows, actions and actionLabel. Explicit actions return `{ok,message}` and optional `path`; CLI exits nonzero for any unconfirmed/partial result. No action is performed without `--apply`. Unknown/stale IDs are rejected against fresh bounded membership. `restore:last` is accepted only when a matching durable receipt exists and does not require the applied theme's catalog row. A different selected row is not authorization to restore the last operation. Theme actions omit action-result capability hints, preserving the normal post-success catalog refresh.

All selected source paths come from fixed local roots, not QML-supplied paths. Directory traversal uses directory FDs and O_NOFOLLOW for every component; symlinked roots, files and ancestors are rejected. The sole deliberate symlink reader is Omarchy's known current-background link; its target is separately allowlisted and opened safely before use. No arbitrary root/config/template input or remote thumbnails. Local previews are original installed/user files, not bundled art. Filenames are bounded/plain text; control characters are excluded. Image admission checks file type, byte limit and signatures; PNG dimensions are additionally capped. Catalog image previews are not a general-purpose hostile-media sanitizer; Qt/codec rendering is outside the backend suite.

Limits: 1024 entries per scanned directory (an overfull directory is skipped, not partially trusted), 32 MiB per preview image, 64 KiB metadata reads, 8192-byte restore receipt, 256 displayed rows, <=1 MiB CLI output. Theme identity is the canonical installed slug; the complete bounded theme tree is revalidated for actions. No arbitrary recursive disk crawl. Content changes during bounded reads are rejected. Process argv is literal, shell=False; stdout and stderr each capped at 64 KiB, hard deadline and process-group SIGKILL on interruption/overflow/timeout, including pipe-holding descendants after their parent exits. Provider stderr is summarized rather than dumping paths/private hook output to the UI.

Plugin-owned state is under `$HOME/.local/state/omarchy-<slug>/`, private modes with an exclusive nonblocking lock and atomic/fsynced receipts. Existing state symlinks and special-file locks are refused. This is not an isolation boundary against malicious programs running as the same Unix user, nor protection from a provider that intentionally daemonizes into another session. Existing Omarchy setters can have their own broad side effects.

## Repeatable offline verification

From this project's root, use the shipped offline runner with TMPDIR naming an existing approved private scratch directory:

```sh
TMPDIR="${TMPDIR:?Set TMPDIR to an existing private scratch directory}" env -u PYTHONPATH PATH=/usr/bin /usr/bin/python3 scripts/run-tests.py --backend-only
```

The runner uses bwrap --unshare-all --clearenv, read-only source/usr/system ImageMagick policy, empty stock fixture, fake HOME, private /run and /tmp, and no host sockets, display or network. It also masks actual theme/background/shell executables with refusal stubs. Every successful setter in tests is a fixture shim inside the box. Inside the cleared box, tests execute `/usr/bin/python3 -m unittest discover -s tests -p 'test_*.py' -v`; the outer invocation explicitly clears PYTHONPATH too. The current runner streams results without creating receipts. The earlier `tests/run_backend_box.py` runner created the historical ignored `release-output/` receipts; those receipts are not shipped or required for the public test command. Do not run unittest on the live session.

Feature RED/GREEN receipts and extra boundary-control receipts are retained under ignored release-output. Runtime feature slices were tested before implementation; additional passing characterization controls were added for existing guards. That failed receipt is preserved.
